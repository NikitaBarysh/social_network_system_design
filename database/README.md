## Репликация

**Тип:** Master–Slave (Hot Standby)  
**Синхронизация:** Асинхронная, push-модель с SBR  
Каждая запись снабжается timestamp, проставляемым на клиенте  
Slave-реплики используются для чтения, Master — для записи

## Шардирование

### 1. Медиа S3
Фотографии хранятся распределённо по шардам в S3
**Тип шардирования:** *по hash(photo_id)*  
**Репликация внутри каждого шарда:** стандартная репликация S3 (3 копии данных) 
**Итого:** ≈206 HDD распределяются по ~70–75 нодам (по 3 HDD/host)

### 2. Метаданные (PostgreSQL)
Для БД, где хранятся посты, лайки, комментарии, используется шардирование по hash(post_id)
Плюсы:
- равномерное распределение постов по шардам
- локальность данных (пост, комментарии и лайки живут на одном шарде)

Каждый шард содержит полный набор таблиц (`posts`, `comments`, `likes`, `users` частично для связи)

**Тип шардирования:** *Hash (по post_id)*  
**Тип репликации:** *Master–Slave (Hot Standby)*  
**Количество реплик:** 2 (1 master + 1 slave)  
**Синхронизация:** асинхронная (push)
